# REAL科研工作台设计说明

> 状态：待用户审阅  
> 日期：2026-09-12  
> 目标：在现有REAL前端基础上，建立可供孙瑞阳和课题组同门使用的私有文献蒸馏与数据库工作台，同时保留GitHub Pages公开展示模式。

本文是总体架构规范。四个里程碑分别作为可独立验收的子项目实施；当前只冻结总体架构和[阶段A论文收件箱设计](2026-09-12-real-workbench-stage-a-inbox-design.md)，阶段B至D在前一阶段确认后再编写各自实施规范。

## 1. 设计结论

采用“同一前端代码、两种运行模式、本地后端、人工准入”的架构：

```text
REAL公开模式（GitHub Pages）
  已审核聚合统计｜研究机制｜公开模型状态｜版本记录
                         ↑ 只发布脱敏聚合结果
REAL私有工作台（本机／实验室局域网）
  论文收件箱｜AI蒸馏｜七表审核｜数据库体检｜科研图｜周报｜M0/M1
                         ↓
本地PDF＋候选数据包＋权威数据库只读接口＋私有GitHub仓库
```

公开模式不提供文件上传、API调用或样品级浏览。私有模式由本地服务提供认证、文件操作、Python任务和结果读取；即使前端代码公开，PDF、API密钥和数据库仍不会离开指定本地目录。

## 2. 为什么选择该方案

### 方案A｜同一REAL代码库双模式＋本地后端（采用）

- 保留导师已经看到的REAL品牌与公开网址。
- 前端组件、科研图和状态口径只维护一套。
- 本地后端可以安全读取PDF、Conda环境、七表脚本和模型代码。
- 首版不购买云服务器，也不把受限论文上传第三方存储。
- 后续可把同一API部署到私有服务器，不推翻前端。

### 方案B｜新建完全独立的私有平台

权限边界最直观，但会形成两个界面项目、两套导航和重复维护，第一阶段成本较高。

### 方案C｜直接在GitHub Pages增加上传和AI按钮

静态页面没有安全后端，API密钥会暴露，浏览器也不能可靠写入本地科研目录，因此不采用。

## 3. 用户角色与权限

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 贡献者 | 上传PDF、填写DOI和补库目标、查看自己的任务、修改候选字段 | 不能确认核心准入、不能写权威数据库 |
| 审核者 | 查看论文证据、修订七表、运行校验、给出核心／辅助／排除意见 | 不能静默覆盖数据库版本 |
| 负责人 | 确认准入建议、导出新版本候选、运行M0/M1、发布脱敏图表与周报 | 仍需显式确认才能形成新权威版本 |
| 公开访客 | 查看已审核统计、科研图和模型状态 | 不能进入工作台或查看私有数据 |

第一版采用本地账户和会话认证。初始负责人由本机配置创建；同门账户由负责人生成。密码哈希和会话密钥保存在本地运行目录，不进入Git。

## 5. 核心工作流

### 5.1 上传与文件登记

```text
选择PDF或扫描本地目录
→ 计算SHA-256
→ 相同哈希立即标记重复
→ 从PDF文本提取DOI候选
→ 人工确认DOI与补库目标
→ 建立只引用本地PDF的候选任务
```

上传页面必须明确显示：文件是否会发送给AI、保存位置、哈希、重复状态和当前用户。PDF默认保存在`研究工作/01_文献/00_未处理/`；同哈希文件不重复复制。

### 5.2 AI蒸馏

```text
核对题目、DOI和版本
→ 建立论文地图
→ 枚举所有真实样品与连续变量
→ 先填sample_master
→ 填光谱、工艺、结构和来源
→ 按统一规则计算组成描述符
→ 建立CIF／局域结构任务
→ 逐字段写入页码、图表和提取方法
→ 生成七表候选包
```

AI调用由后端执行。每次任务保存模型标识、提示词版本、输入文件哈希、开始与结束时间、Token用量和错误信息。模型输出先经过JSON schema校验，再写入现有候选包格式。

### 5.3 审核与准入

候选状态机固定为：

```text
uploaded
→ fingerprinted
→ metadata_confirmed
→ extracting
→ candidate_ready
→ validation_passed / needs_revision
→ human_reviewed
→ approved_for_version / auxiliary / excluded
```

网页中的“通过”只形成新数据库版本候选。第一版不提供“覆盖权威数据库”按钮。负责人需导出候选合并包，在既有数据库审计流程中确认后才能建立新版本。

### 5.4 CIF与局域结构

结构任务分四类显示：样品自身精修、完全相同host实验CIF、完全相同host计算CIF、近似host参考。普通XRD曲线不能自动生成可靠AO₈数据。

```text
有精修坐标／CIF
→ 自动计算A–O键长、AO₈体积和畸变指数

只有晶格参数
→ 保存晶格信息，局域结构保持缺失

只有XRD曲线
→ 进入“需要Rietveld精修”任务
→ 页面给出数据需求、软件步骤和审核清单
```

所有结构代理显示来源、匹配等级和质量等级，不能伪装成样品自身精修。

## 6. 数据存储与仓库边界

### 6.1 本地运行目录

本地后端使用SQLite保存用户、任务、状态和操作日志；科研候选数据继续保存为CSV、YAML、JSON和WPS Excel，便于Git比较和人工复核。

```text
研究工作/01_文献/00_未处理/       本地PDF
研究工作/02_数据库/01_单篇提取表/ 候选提取成果
REAL_RUNTIME_ROOT/real_workbench.db 任务与权限元数据
REAL_RUNTIME_ROOT/jobs/              临时任务输出与日志
```

运行根目录必须通过显式环境变量配置，禁止用浏览器传入任意绝对路径。

### 6.2 GitHub职责

- `real-materials-showcase`：公开前端、私有工作台前端与本地后端代码，不提交运行数据。
- `real-materials-research`：项目规则、脱敏快照、模型、图表、报告和状态。
- `real-materials-paper-vault`：DOI清单、论文哈希、候选包、证据索引和蒸馏SOP。
- 本地`研究工作`：PDF、权威Excel和未脱敏数据。

候选包只有通过隐私和版权扫描后才能提交私有论文库。公开站只接收聚合JSON和已核验图表。

## 7. 技术架构

```text
React 19＋TypeScript＋Vite
        │ HTTP / Server-Sent Events
FastAPI＋Pydantic＋SQLite
        │
        ├── 文献候选包适配器
        ├── OpenAI模型适配器
        ├── PDF文本／页面证据适配器
        ├── 描述符与CIF任务适配器
        ├── 数据库审计与快照适配器
        ├── M0／M1运行适配器
        └── 科研图／Markdown周报适配器
```

Python后端复用`real-materials-m0` Conda环境。长任务通过本地任务队列串行执行，前端用Server-Sent Events显示进度；首版不引入Redis、Celery、Docker集群或GPU。

OpenAI API Key仅由后端环境变量读取。浏览器只提交任务参数，不接触Key。PDF发送给外部模型前，界面必须再次显示文件名、用途和发送确认。

## 8. API合同

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/v1/session/login` | 登录私有工作台 |
| `GET` | `/api/v1/dashboard` | 返回任务、数据库和模型聚合状态 |
| `POST` | `/api/v1/documents` | 上传PDF并计算哈希 |
| `POST` | `/api/v1/documents/scan` | 扫描固定未处理目录 |
| `PATCH` | `/api/v1/documents/{id}` | 确认DOI、家族和目标字段 |
| `POST` | `/api/v1/documents/{id}/extract` | 启动AI蒸馏 |
| `GET` | `/api/v1/jobs/{id}/events` | 流式读取任务进度 |
| `GET` | `/api/v1/packages/{id}` | 读取七表、证据和校验状态 |
| `PATCH` | `/api/v1/packages/{id}/tables/{table}` | 保存人工修订 |
| `POST` | `/api/v1/packages/{id}/validate` | 运行现有候选包校验器 |
| `POST` | `/api/v1/packages/{id}/review` | 保存人工准入意见 |
| `GET` | `/api/v1/database/health` | 返回家族、字段和来源覆盖 |
| `POST` | `/api/v1/figures/render` | 生成版本化科研图 |
| `POST` | `/api/v1/reports/weekly` | 生成导师周报候选稿 |
| `POST` | `/api/v1/models/runs` | 运行M0或M1版本对照 |

所有写操作记录用户、时间、输入哈希和前后状态。删除、覆盖和权威版本发布不属于第一版API。

## 9. 页面设计

私有工作台沿用当前REAL视觉语言，但从“长页宣传结构”转为“科研控制台”：

- 左侧固定导航表示工作流阶段；顶部显示当前数据版本、运行环境和API余额状态。
- 总览首屏以一条文献处理流水线为主视觉，直接显示每个阶段的数量和阻塞。
- 文献收件箱采用高密度表格，突出文件、DOI、家族、哈希和下一动作。
- 七表审核使用主表＋证据抽屉；点击数值即可看到PDF页码、图表、提取方法和质量等级。
- 数据库状态页以家族分布、字段覆盖、DOI独立性和M0/M1准备度为主。
- 科研图页采用“图表＋一句科研判断＋导出”结构，支持SVG、PNG和Markdown。
- 周报页按“本周完成—数据变化—模型结果—问题—下周行动”自动组装，所有数字链接回版本证据。

状态除颜色外必须带文字和图标；危险动作采用二次确认；移动端支持查看与简单审核，批量编辑和模型运行以桌面端为主。

## 10. 第一版里程碑

### 阶段A｜可运行的论文收件箱

- 双模式构建和私有工作台壳层；
- 本地FastAPI、SQLite和登录；
- 上传／扫描PDF、SHA-256去重、DOI确认；
- 显示当前未处理文件、重复文件和下一动作；
- 不调用AI，不修改科研数据。

### 阶段B｜七表AI蒸馏与审核

- 接入现有schema、受控词表和候选包脚本；
- 接入OpenAI API任务和结构化输出；
- 论文地图、样品枚举、字段证据和七表编辑；
- 自动校验、WPS导出和人工准入意见。

### 阶段C｜数据库状态、科研图与周报

- 读取权威库只读统计、候选增量和家族缺口；
- 生成家族、光谱、字段、来源和每周进度图；
- 生成导师周报Markdown并冻结素材清单；
- 审核后发布脱敏聚合结果到公开模式。

### 阶段D｜M0与M1版本对照

- 从确认候选生成新训练快照候选；
- 使用相同DOI分组合同运行M0和M1；
- 展示MAE、RMSE、MSE、R²、家族中心偏差和学习曲线；
- 记录模型、数据、代码和图表版本，不发布未验证数值。

每个阶段完成后停止，向用户提供页面预览、测试结果、GitHub链接和数据边界；只有收到“无误继续”才进入下一阶段。

## 11. 第一版验收标准

- GitHub Pages继续构建公开模式，现有公开内容和8项测试不回退。
- 私有模式在`real-materials-m0`环境中一条命令启动前后端。
- 两名不同账户可以在局域网提交任务并看到明确归属。
- 相同PDF哈希不会形成两份候选任务。
- 未确认DOI的文件不能启动正式蒸馏。
- 每个AI生成数值都能打开对应来源位置或显示“证据缺失”。
- 七表校验、Excel导入导出与现有论文库脚本保持兼容。
- 网页审核不能直接修改权威Excel和冻结快照。
- 科研图和周报数字来自指定数据版本，不在前端手写统计。
- M0/M1结果明确显示数据版本、分组方式、模型版本和适用边界。
- API Key、密码、PDF和绝对路径不会进入Git、浏览器响应或公开构建产物。
- 桌面与移动端完成可访问性、越界和错误状态检查。

## 13. 明确不在第一版实施的内容

- 直接覆盖权威Excel或自动更新冻结训练快照；
- 在公开GitHub Pages上传PDF或保存API Key；
- 自动宣布候选样品进入核心数据集；
- 未经确认自动下载受版权限制论文；
- 由普通XRD图片自动伪造Rietveld精修坐标；
- 全实验室LIMS、仪器联网、GPU训练集群或复杂云端调度；
- 向公开访客展示样品级私有数据或未经验证的模型预测。
